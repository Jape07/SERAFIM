# SERAFIM

SERAFIM shows how SPHEREx images of the sky change over time. A Python pipeline turns public
SPHEREx images from IRSA into small Parquet tables and PNG files ("gold"), and a static site on
GitHub Pages reads them directly in the browser with DuckDB-WASM. There is no server.

Site: https://jape07.github.io/SERAFIM/

## Architecture

Medallion layers in a single Python repo, GitHub Actions as the engine and a static site on
GitHub Pages. Everything heavy happens before publishing; the browser only reads gold.

```text
IRSA (SPHEREx) ──> bronze ──> silver ──> gold ──> web (GitHub Pages)
                                  │         ▲
                                  └─> AI & validation (catalogs, guides, spectra, light curves,
                                      trajectory, verification, dipoles)
```

| Layer | What it stores | Format | Published? |
| --- | --- | --- | --- |
| Bronze | FITS cutouts exactly as they come from IRSA, plus `manifest.parquet` | FITS, Parquet | No |
| Silver | Clean, aligned images, difference images and detections | NumPy (`.npz`), Parquet | No |
| Gold | Final tables and PNG files for the website | Parquet, PNG, JSON | Yes |

Each layer only reads the previous one, bronze is never modified and every step is idempotent.

## How each target was validated

Every number comes from reports regenerated on the gold the site serves (task A8,
[docs/mvp_review.md](docs/mvp_review.md)).

| Target | The challenge asks to see | How we checked it | Result |
| --- | --- | --- | --- |
| Barnard's Star | its motion | Its position fitted in every season against the catalog motion, parallax included; the dipole rule searched blind | 10.45 ± 0.38″/yr measured, 10.40 in the catalog ([trajectory](docs/trajectory.md)); found in all 6 detectors ([dipoles](docs/dipoles.md)) |
| Epsilon Indi B | its motion and its spectrum | The same fit, and forced photometry of every frame | 4.58 ± 0.28″/yr vs 4.62; methane: 3.3 µm over 4.1 µm = 0.22 ([verification](docs/verification.md), [spectra](docs/spectra.md)) |
| WISE 0855 | that SPHEREx sees it | Its flux at its catalog position in every sum, with its G 16.3 neighbour fitted too | Seen only in detector 6 (S/N 7); W2 flux 0.93 of the catalog's ([visibility](docs/visibility.md)) |
| RW Aurigae | a change of brightness | Photometry of the glow around its saturated center, against Barnard's Star as a control | 1.54 times brighter in detector 1 after a year ([light curves](docs/light_curves.md)) |
| R Draconis | a change of brightness | The same, and a period search on SPHEREx alone | 244 days found, 247 in the catalogs ([light curves](docs/light_curves.md)) |

On the published site: the gold contract passes, the verification of the five targets has no
failure ([docs/verification.md](docs/verification.md)) and no catalog marker is out of place
([docs/markers.md](docs/markers.md)). Limits, said on the site too: saturated stars give no
reliable spectrum, and WISE 0855 is too faint to follow season by season. Live demo:
[docs/demo.md](docs/demo.md).

## Gold contract

The source of truth is [`serafim/contract.py`](serafim/contract.py). Agreed in issue #18
(task D2); any change needs approval from all three roles.

| File | One row per | Columns | Filled by |
| --- | --- | --- | --- |
| `targets.parquet` | target | target_id, name, kind, ra_now, dec_now, pmra_mas_yr, pmdec_mas_yr, size_deg, wcs_json | data |
| `frames.parquet` | single exposure | frame_id, target_id, obs_id, collection, date_utc, season, detector, wavelength_um, bandwidth_um, flags, saturated | data |
| `sums.parquet` | detector × season | sum_id, target_id, detector, season, mean_date_utc, n_frames, background_noise, flags, saturated, png | data |
| `differences.parquet` | detector × pair of seasons | difference_id, target_id, detector, season_a, season_b, png | data |
| `catalogs.parquet` | catalog source at one date | target_id, catalog, name, season, date_utc, ra, dec, mag, mag_band, url | AI |
| `spectra.parquet` | photometry point | target_id, frame_id, season, date_utc, wavelength_um, flux_mjy, error_mjy, flag | AI |
| `trajectory.parquet` | target × season | target_id, season, ra_measured, dec_measured, error_arcsec, ra_catalog, dec_catalog | AI |
| `meta.json` | pipeline run | run_date_utc, commit, collections, last_frame_date_utc, n_frames | data |

- **The image the site shows is the sum** of the frames of one detector (1 to 6) in one season.
  Differences are between seasons, season b minus season a.
- **`detector = 0`** is the white image (all detectors of that season) and **`season = 0`** is
  every season of that detector.
- **`catalogs`** has each source moved to `date_utc`, so the markers move with the video: for
  Gaia, CatWISE and SIMBAD the mean date of each season, and `season = 0` for the mean date of
  every frame. SkyBoT has one row per visit, so an asteroid has several rows in a season.
  `mag` is in the band `mag_band`: `G` (Gaia), `W2` (CatWISE) or `V` (SIMBAD, SkyBoT).
- **A cell without frames has no row and no PNG**: the site skips it. The color image
  needs detectors 1, 3 and 6, so it does not exist in a season that lacks one of them.
- **PNG names** (relative to `gold/`, never changed without telling web):
  `png/<target>/sum_d<detector>_s<season>.png`, `png/<target>/diff_d<detector>_s<a>-s<b>.png`
  and `png/<target>/color_s<season>.png`.
- **`kind`** is `motion`, `brightness`, `spectrum` or `custom` (targets added by coordinates).
- **`flags`** is text with the flag names separated by commas, never `SOURCE`
  (for example `BLOOM,OVERFLOW`; empty when none). In pandas use `df["flags"]`, because
  `df.flags` is a pandas attribute.
- **`saturated`** means the target pixel is empty (OVERFLOW or NONLINEAR): the site shows
  "saturated center". The PNGs paint those pixels with the brightest color.

`python -m serafim mock` writes simulated gold that follows this contract (one target, 6
detectors, 3 seasons, one missing cell and a saturated center); `--all-targets` writes all 5.

## Getting started

Use Python 3.11 (the same version as GitHub Actions).

```bash
git clone https://github.com/Jape07/SERAFIM.git
cd SERAFIM
py -3.11 -m venv .venv          # macOS/Linux: python3.11 -m venv .venv
.venv\Scripts\activate          # macOS/Linux: source .venv/bin/activate
pip install -e ".[dev]"         # everyone
pip install -e ".[dev,ai]"      # AI & validation: adds PyTorch, Optuna and ONNX
ruff check .
pytest
```

Run the site locally with simulated gold:

```bash
python -m serafim mock          # simulated gold in data/gold/
cp -r data/gold web/gold        # web/gold/ is git-ignored
python -m http.server 8000 -d web
```

## How we work on GitHub

- One task = one branch = one small PR. Nobody pushes to `main`; `main` must always be publishable.
- Branch prefixes: `data/`, `ai/`, `web/` (for example `ai/A1-catalogs`).
- Commit messages: `type(area): what it does`, with type `feat`, `fix`, `test`, `docs` or `chore`.
- Every PR says what it does, `Closes #<issue>` and how it was verified. Web PRs need before and
  after screenshots.
- Reviews: data engineering and AI & validation review each other; web PRs are reviewed by
  whoever is free first. Goal: under 15 minutes.
- Merge with "Squash and merge" and delete the branch.
- If `main` moved: `git pull --rebase origin main` and `git push --force-with-lease`, only on
  your own branch.
- Labels: `data`, `web`, `ai`, `blocker`.
- Tags: `v0.1-mvp` at H14 and `v1.0` at delivery.
